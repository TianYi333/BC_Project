## 对齐 H743 的重连修复 + 新增 OTA 超时看门狗
参考 `D:\Desktop\H743_VS_GCC_IDE` 当前版（与其 `_ota_backup_20261012` 备份 diff 确认改动点），对本工程做两处移植（SC 专属适配）：

1. **重连健壮性修复**（`UserCode/Drivers/ETH/net_comm_task.c` 的 `tcp_recv_cb`）：
   - 旧版 `p==NULL` 时无条件 `tcp_pcb=NULL` → 留下 CLOSE_WAIT 孤儿连接（"PC 看到两条连接 / 重连只断一条"根因）。
   - 改为仅 `err!=ERR_OK`（异常路径，lwIP 会自释放）才清 `tcp_pcb`；优雅 FIN（`p==NULL && err==ERR_OK`）故意保留 `tcp_pcb`，交主循环 `safe_tcp_close()` 真正 `tcp_close` 释放。
   - H743 的 `tcp_client_task` 重连主体、其它重连机制（reconnect_tick / g_fast_reconnect / hb_lost_cnt / safe_tcp_close / ETH 链路检测）SC 早已具备且与 H743 一致，未动；`tcp_error_callback` 两边都是无条件清 `tcp_pcb`（正确），未动。

2. **OTA TFTP 接收超时看门狗**（新增，`UserCode/Drivers/ota/ota.c`）：
   - `OTA_TFTP_RX_TIMEOUT_MS`(默认 30000) + `g_ota_last_active_tick` / `g_ota_rx_timeout_ticks` / `g_ota_mon_task`。
   - 新增 `ota_check_timeout()` / `ota_monitor_task()`（独立低优先级任务，1s 轮询）/ `ota_start_monitor()`（幂等）。
   - 在 `tftp_open_cb`(WRQ 成功) / `tftp_write_cb`(DATA) / `ota_handle_upgrade_start`(TFTP 启动) 三处刷新活动时间并启动看门狗。
   - SC 适配要点：CMSIS V1——`osThreadDef`+`osThreadCreate` 替代 H743 的 `osThreadNew`；`HAL_GetTick()`(ms) 替代 `osKernelGetTickCount`/`osKernelGetTickFreq`（SC 重连计时也用 HAL_GetTick，风格一致）。`osThreadDef` 必须放在函数前向声明之后（V1 宏把函数指针直接写进 const 结构体，前置声明必须先于它）。
