============================================================
一、新增：心跳报文 uptime 字段（设备运行时间）
============================================================
1. 字段语义
   - 键名 "uptime"，整型，单位秒（截断取整，误差 ≤1s）
   - 取值 HAL_GetTick()/1000（本工程 F767 时基同为 TIM7 1ms），开机为 0 点，
     约 49.7 天回绕
2. 修改后心跳报文示例（8 路在线状态数组）：
   {"device_id":"...","sensor_online":[1,1,0,1,0,0,1,1],"seq":42,"status":0,
    "ts":1795133180,"type":"heartbeat","uptime":86400,"sign":"A1B2C3D4"}
3. 代码改动（UserCode/Drivers/ETH/net_comm_task.c 单处；本工程心跳为"排序式组包"，
   与 LUB 系列不同，无需改头文件与结构体）
   - tcp_send_heartbeat()：在 root 对象 "type" 键之后追加
     cJSON_AddNumberToObject(root, "uptime", HAL_GetTick() / 1000U);
   - 该函数签名走 cjson_sort_recursive(root) 递归字典序规范化后序列化再算 HMAC，
     "uptime"（t<u）自动排在 "type" 之后，最终报文与签名原文顺序一致、sign 恒在末尾
   - 顶层字段注释同步更新：device_id → sensor_online → seq → status → ts → type → uptime
4. 协议契约影响（重要）
   - 心跳 HMAC-SHA256 验签原文新增 "uptime":N，网关侧签名计算必须同步纳入该键，
     否则升级后所有心跳 sign check failed。需与网关同版本发布。

Heartbeat gains integer-seconds "uptime" (= HAL_GetTick()/1000, zero at boot, wraps
after ~49.7 days). Unlike the LUB family, this project builds the heartbeat as one
object and normalizes it with cjson_sort_recursive() before signing, so a single
insertion after "type" suffices; no struct/header change. "uptime" sorts right after
"type" (t < u) with "sign" appended last. The gateway MUST include "uptime" in
heartbeat signature computation before deploying this firmware.
