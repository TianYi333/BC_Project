## RS485 通道「上电前接了传感器 → 该口上电后收不到数据且不再进中断」诊断
- 现象：某路 RS485 若在 MCU 上电**之前**就已接好并通电的传感器，该路上电后收不到数据、也不再进 UART 中断；未接传感器的通道正常。
- 根因（未改代码，仅诊断）：
  1. 上电窗口期：从 `MX_USARTx_UART_Init()`（此时 RX 已使能 RE=1）到 `SensorHub_Init()` 里 `HAL_UARTEx_ReceiveToIdle_IT/DMA()` 启动接收，中间有几百 ms~数秒（RTOS 启动、任务创建）。这段时间传感器发来的数据没人读 RDR → **ORE（溢出）置位**；总线/收发器未稳还会带 FE/NE。
  2. 一使能 RXNEIE/IDLEIE，ORE 立刻触发中断 → `HAL_UART_IRQHandler` 走 error 分支 → 调用 **weak 空实现** 的 `HAL_UART_ErrorCallback`（**全工程无用户强实现**）→ HAL 把 `RxState` 置回 READY、关接收中断、停 DMA → 该通道永久死掉。
  3. 佐证：`sensor_hub.c:104-139` `SensorHub_Init()` 启动接收前**无清标志/冲刷 RDR**；grep 全工程 `HAL_UART_ErrorCallback` 只有 HAL 库 weak 版本（map 0x080a56c4）；`usart.c` 各 RX 引脚均为 `GPIO_NOPULL`（空闲时易收噪声）。
- 待实施的修复（待用户确认）：
  A. `SensorHub_Init()` 启动接收前冲刷：读 RDR 丢弃残留 + `SET_BIT(RQR, USART_RQR_RXFRQ)` + 写 `ICR` 清 PE/FE/NE/ORE/IDLE + `ErrorCode=NONE` + `RxState=READY`。
  B. 在 `sensor_hub.c` 实现 `HAL_UART_ErrorCallback()`：清标志后重启 `ReceiveToIdle_IT/DMA`，让运行期干扰/从机乱码也能自愈（否则一次 ORE 永久掉一路）。
  C. `.ioc` 里把各 RS485 的 RX 引脚 `GPIO_NOPULL` → `GPIO_PULLUP`（CubeMX 生成区，须改 ioc 重新生成才不丢）。
- 快速判据（未验证）：**上电完成后再插传感器**若能正常收 → 100% 坐实上电窗口期的错误标志问题。

## 已实施（A+B+C，编译 0 error/0 warning，FLASH 204220B = 384KB 的 51.94%）
- **A** `UserCode/Drivers/RS485/sensor_hub.c`：新增 `sh_uart_flush_rx()`（读 RDR → `SET_BIT(RQR, USART_RQR_RXFRQ)` → 写 `ICR` 清 PE/FE/NE/ORE/IDLE → `ErrorCode=NONE` + `RxState=READY`）与 `sh_start_rx(idx)`（flush + 按 DMA/中断启动 ReceiveToIdle）；`SensorHub_Init()` 改为调 `sh_start_rx(i)`。
- **B** 同文件新增 **`HAL_UART_ErrorCallback()`**：定位端口 → DMA 路先 `HAL_UART_DMAStop()` → `sh_start_rx()` 重启接收，让运行期干扰/从机乱码也能自愈（此前全工程只有 HAL 的 weak 空实现）。
- **C** `Core/Src/usart.c`：8 路 RX 在各自 `USER CODE BEGIN UARTx_MspInit 1` 保护区里用 `MODIFY_REG(GPIOx->PUPDR, 3<<(n*2), 1<<(n*2))` 改上拉（UART4 PC11 / UART5 PB12 / UART7 PF6 / UART8 PE0 / USART1 PB15 / USART2 PD6 / USART3 PB11 / USART6 PC7）。**写在保护区，CubeMX 重生成不丢**，不必改 .ioc（回答用户"手动改可以吗"：可以，但必须放 USER CODE 区，直接改生成区会被覆盖）。
- 踩坑：F7 CMSIS 的噪声清除标志叫 **`USART_ICR_NCF`**（不是 `NECF`）；`HAL_UART_ErrorCallback` 定义在 `sh_start_rx` 之前需加静态前向声明，否则 implicit declaration + static 冲突报错。

## FC06 回显尾部冗余字节修复（2026-09-14 16:44）
- 实测（串口助手抓总线）：传感器对 FC06 的回显 = 请求帧 8 字节原样回传 + **尾部多 1 个 0x00**（9 字节，CRC F9 CB 本身正确）；sh_write_resp_match 原来要求 len==8 → 匹配失败 → 写方 500ms 超时报离线。
- 修复：sh_write_resp_match 改为 len 8~16 均接受，只校验前 8 字节（addr/func/reg/value/CRC），尾部忽略（SH_WRITE_RESP_MIN/MAX_LEN 宏）。传感器实际已生效，只是判定过严。
