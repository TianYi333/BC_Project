## [OTA] meta state=0x04000002 异常诊断
- 现象：App 启动打印 `[OTA:336] meta magic=0x4C55424F state=67108866 (0x04000002)`。
- 拆解：低字节 `0x02`=DONE（正确），高字节 `0x04` 是垃圾位 → 当前 32B 读取把高字节当成 state 一部分。
- 排查：App/Boot 的 `ota_meta_t` 字节级一致（32B，magic@0/state@4）；git 单提交 `340e789`(09-14) 引入后从未改；枚举 0~4；H7 派生源 `/d/Desktop/boot` 也是同款 32B 结构。**无任何代码路径写 0x04000002。**
- FAL 校验：`stm32_onchip` 设备基址=0x08020000，ota_meta 分区 offset=448*1024 → 物理 0x08090000，**与 Boot `OTA_META_OFFSET` 完全一致** → 不是读错扇区。
- 结论：S16(ota_meta) 扇区里是**旧版固件遗留的 meta**（旧结构把 flags/version 字打进 state 高字节，或 state 是更小类型）；很可能是烧录新 boot+App 时未擦 S16，旧实验 meta 残留。
- 影响：无害启动（boot `default` 分支→跳 App；App `ota_app_confirm` 见 `state!=DONE` 跳过）；但垃圾值持续、且会掩盖真正 pending 的 OTA。
- 修复方向（待用户确认）：(A) 代码自愈——`ota_app_confirm` 遇 `magic` 正确但 `state∉{0..4}` 则擦 meta→NONE；(B) 一次性 CubeProgrammer/调试擦 S16(0x08090000)。

## [OTA] meta magic 变垃圾 + "不能正常更新" 根因坐实
- 现象升级：用户复现 `meta magic=0x4CD563DF state=1179099883(0x4647AE2B)`——magic 也变垃圾，S16 整体是随机/旧固件残留（不再是上轮的"合法 magic+脏 state"）。
- 复查排除：KVDB 受分区 `len` 限制绝不溢出进 S16；App/Boot 的 meta 写入均写合法 magic 且关中断+.RamFunc 同 Bank 安全；FAL `ota_meta` 物理=0x08090000 与 Boot `OTA_META_OFFSET` 一致 → 垃圾非当前代码输出。
- **用户验证（本轮回）**：CubeProgrammer 擦除整个 Flash 后 OTA 正常升级 → 根因就是 S16(及可能的 firmware_a/KVDB) 旧残留挡住 OTA 握手（boot 读不到合法 PENDING）。一次性整片擦除清掉残留即恢复。
- 结论：属一次性遗留状态，非代码 bug；当前 OTA 代码每次成功都写合法 meta，正常流程不复发。
- 可选加固（**已实现 2026-09-17**，用户说"实现"）：用户确认后落地 A+B。
  - A 自愈：App `UserCode/Drivers/ota/ota.c` 新增 `ota_meta_sanitize()`（擦 S16+写 NONE）；`ota_app_confirm()` 遇 `magic!=OTA_META_MAGIC || state>OTA_STATE_FAILED` 调它。`SensorConcentrator_boot/Core/Src/main_boot.c` 在"无 magic 分支(双 Bank 下)"与"switch default 分支"均置 NONE 并 `write_meta()`。
  - B 判错日志：`ota_on_complete()` 现检查 `fal_partition_erase/write` 返回值并 `LOG_OTA` 报错。
  - 验证：App `cmake --build build/Debug`(ninja) 通过，FLASH 205236B；Boot 另配 Ninja 到 `build_ninja` 构建通过(8040B) 后删该临时目录，原 `build/` 不变。
