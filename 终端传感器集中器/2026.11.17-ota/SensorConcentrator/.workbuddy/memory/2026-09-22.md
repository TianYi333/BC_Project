# 2026-09-22 工作日志

## CH1 调试口一键开关宏（DEBUG_UART_ENABLE）
- 需求：开发时 CH1/UART7 作调试打印口，量产时一键恢复 CH1 为传感器采集。
- 实现（已落盘、双配置均编译通过）：
  - `UserCode/Drivers/RS485/sensor_hub.h`：新增总开关 `DEBUG_UART_ENABLE`（默认 1）；`SH_DEBUG_UART_ID` 改由其派生（=1→1 即 CH1，=0→0 不占用任何路）。CH1 恢复为传感器采集的逻辑原本就靠 `#if SH_DEBUG_UART_ID` 在 `=0` 时整段删除实现，无需改 sensor_hub.c。
  - `UserCode/Drivers/RS485/debug_uart.c`：原 `#if SH_DEBUG_UART_ID` 整体增加 `#else` 空实现分支（`DebugUart_Init/Flush/DumpHex/Panic/PanicHex` 全变 no-op，且不提供 `_write_r`/`__io_putchar` 使 printf 无输出且被 gc 丢弃）→ 解决 `=0` 时 main.c/sensor_hub.c/stm32f7xx_it.c/fal 驱动调用未定义导致的链接失败。
  - `debug_uart.h`：同步更新用法说明。
- 验证：`=1`（默认）与 `=0`（临时切 0 编译通过后已还原）均 `cmake --build build/Debug` EXIT=0、链接通过；`=0` 固件 209612B 略小于 `=1` 的 210892B。
- 用法：量产改 `sensor_hub.h` 中 `DEBUG_UART_ENABLE` 为 0 重编即可。

## 设置通道 mode 后读回真实状态更新全局变量
- 需求：mode_set_req 写完某路 mode(FC06 写 0x0007)后，再用 FC03 读回该路实际状态，用真实值更新全局，避免“写回显通过但传感器实际未生效”导致全局与实际不一致。
- 并发约束（关键点）：`g_sensor_frame_queue` 由 `SensorHub_Task` 独家消费，FC03 读应答是入队帧，不能在 net_comm_task 里直接 `xQueueReceive` 抢队列 → 复用写同款**信号量**机制。
- 实现（已落盘，`cmake --build build/Debug` EXIT=0、无告警、符号均编入）：
  - `sensor_hub.c`：新增 `ShReadSync_t g_rd_sync[8]`（结构同 ShWriteSync_t，含 armed/reg/value/sem），`SensorHub_Init` 中一并创建信号量；新增 `sh_read_resp_match()`（在 `SensorHub_Task` 主循环 `sh_write_resp_match` 之后调用，匹配本路 FC03 读应答并释放读信号量）；新增 `SensorHub_ReadReg()`（FC03 读 + 阻塞等信号量，返回寄存器值）；新增 `SensorHub_ReadModeBack()`（读回真实值 → 更新 `g_sensor_mode[]` 与 `g_sensor_cache[].data.mode`，后者加 `g_cache_mutex` 保护）。
  - `sensor_hub.h`：新增 `SensorHub_ReadReg` / `SensorHub_ReadModeBack` 原型。
  - `net_comm_task.c`：`sensorhub_write_mode` 写成功后调 `SensorHub_ReadModeBack` 更新全局；读回失败(超时/CRC)用期望值兜底 `sensorhub_set_mode`；移除原 mode_set 处理里冗余的 `g_sensor_mode[..] = req_mode`（改由读回/兜底统一更新）。读回代码与 BootProbeModes 同置于 `#if !SH_LOOPBACK_ECHO` 内，回显测试构建不受影响。
- 验证：默认配置(DEBUG_UART_ENABLE=1, SH_LOOPBACK_ECHO=0) 编译通过、链接通过，bin 210644B；`nm` 确认 `SensorHub_ReadModeBack/SensorHub_ReadReg/sh_read_resp_match/g_rd_sync` 均存在；改动文件无告警。
