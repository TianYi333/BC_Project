一、注油失败原因细分上报
============================================================
文件：UserCode/Logic/running_logic.c，inject_running() 内

原逻辑：waiting_met_sen(...) == 0 判失败，错误串固定为
        "WATING_MET_SEN_FAILURE !"，现场无法判断是哪一种失败。

现改为捕获返回值并按返回码细分：
  uint8_t met_sen_ret = waiting_met_sen(main_sys_status.q_model.point.pipe);
  if (met_sen_ret != 1) { ... }

生成错误串（按返回码 switch，最长 46 字节，适配 error_msg[48]）：
  WATING_MET_SEN_FAILURE !(2:p=%u invalid)          sen_id非法(>2)
  WATING_MET_SEN_FAILURE !(3:p=%u g=%u r=%u 2s)     2s队列等待超时
  WATING_MET_SEN_FAILURE !(4:p=%u g=%u r=%u)         系统总超时
  WATING_MET_SEN_FAILURE !(5:p=%u g=%u r=%u)         未知
  WATING_MET_SEN_FAILURE !(ret=%u)                  兜底

同时附带本次现场观测值，用于区分"电机没到位"与"传感器组合不对"：
  p = 期望的传感器ID(point.pipe)
  g = Read_MET_Sensor() 组合结果 (0=都不在/都触发, 1=SEN_1, 2=SEN_2)
  r = 原始电平位 (bit0=SEN_1, bit1=SEN_2)

输出：
  串口  met sen err ret=%u pipe=%u got=%u raw=%u (s1=%u s2=%u)
  OLED  sen p%u g%u r%u
  上报  inline_report_result(...) 与 record_injector_err(...) 均改用带码串 met_sen_err

二、修复：上电传感器确认是空检查（bug）
============================================================
文件：UserCode/Logic/running_logic.c，start_running() 内

  旧：if (waiting_met_sen(motor_loc_list[0].pipe) > 0)
  新：if (waiting_met_sen(motor_loc_list[0].pipe) == 1)

原因："> 0" 会把超时(3)、系统超时(4)、未知(5) 全当成成功，
导致上电时"阀芯传感器到位确认"实际是空检查——传感器没到位也照样
往下走（走到 motor_loc_list[1] 并切 SYS_MODE_READY），
带着未确认的阀芯位置继续运行。
改后超时走 else 分支：报 Q_MODEL_RESET_FAILURE + OLED "init sen error"，
并保持 SYS_MODE_STARTING 等待重试。

============================================================
三、修复：电机归零失败不再"带病启动"（bug）
============================================================
原逻辑：上电 zdt_run_motor_zero() 失败只打一条日志就继续跑，
带着未验证的零点基准执行绝对角度指令，阀芯会停在错误的物理位置。

现改为 4 处配合：

1) 新增状态标志（UserCode/Logic/running_logic.c 定义，
   running_logic.h 声明 extern）：
     g_q_zero_ready  1=Q已归零，角度基准可信
     g_p_zero_ready  1=P已归零
   放在普通 .bss（不使用 ._DTC_FSRAM），掉电/重启后自动清零，
   必须重新归零才能运行，符合"基准不可信则停机"的安全语义。

2) 上电归零改为有限重试（running_logic.h 新增 MOTOR_ZERO_MAX_RETRY = 3）：
     最多重试 3 次，每次间隔 500ms；
     成功则置对应标志=1；
     仍失败则保留原有的 sys_warning + logInfo + OLED 告警。

3) 阻断点放在绝对定位入口：
     q_motor_run_point() / p_motor_run_point() 开头检查对应标志，
     为 0 则直接 return 0 并告警，**不发出任何 0xFD 绝对角度指令**。
     这两个函数是全部绝对定位指令的唯一出口，一处拦住所有下游动作
     （start_running / inject_running / q_motor_run_open / q_motor_run_close）。

4) 恢复路径（UserCode/Logic/oled_page.c）：
     Q/P Model Init 菜单页手动置零（zdt_set_motor_reset_zero）成功后，
     置对应标志=1，自动解除阻断，无需重启。

四、注释修正
============================================================
文件：UserCode/Logic/running_logic.c，waiting_met_sen() 上方

原注释与代码不符（说 sen_id 超出合法范围是 0/1/2、pipe=0 直接返回0），
已修正为如实描述：合法 sen_id 范围固定为 0/1/2，sen_id>2 才是非法；
sen_id==0 不进入等待循环，会落到函数末尾 return 5（调用方视为失败）。

五、Unit Test 传感器映射诊断（临时诊断代码，未同步到衍生工程）
============================================================
文件：UserCode/Logic/oled_page.c

新增两个静态函数，用于核对 motor_loc_list[].pipe 是否与该位置
实际被触发的传感器一致：

  print_q_sen_map(_MOTOR_LOC point)   串口诊断
      输出 [SENMAP] id=%d deg=%d pipe=%d -> s1=%d s2=%d g=%d OK/NG
      在 unit_test 每次移动到新位置后调用

  show_q_sen_map(void)                OLED 状态栏常驻显示（无串口时用）
      格式 "id<位置号> p<期望pipe> s<sen1><sen2> g<组合值> OK/NG"
      例："id2 p1 s01 g2 NG" = 该位置期望1号传感器，实际是2号被触发
      OLED 消息 4s 无刷新会自动清除，故在 unit_test 主循环中周期性刷新保持常驻

  读数含义：
      p = 期望值（表里的 pipe）  g = 实际组合值  OK ⇔ g == p
      匹配须精确相等：p=1 需 g=1；p=2 需 g=2；g=0 或 g 为另一个值都算不匹配。

注意
============================================================
1. 归零标志为 0 时系统会拒绝一切绝对定位并提示 "Q zero not ready !"，
   需进 Q Model Init 手动置零后才能恢复运行。
   手动置零务必先把阀芯停在 SEN_2（pipe2）触发位再按 PUSH，
   否则会引入 180° 错位（表现为期望 SEN_1 实测 SEN_2，即 p1 g2）。

2. 第五节的 unit test 诊断代码属排查阶段临时工具，
   未同步到两个 V2.0 衍生工程。

3. 本工程的 q_motor_run_open/close 中 switch(point.id) 的反转点为
   case 8 / case 2，与 V2.0 衍生工程的 case 9 / case 3 不同，
   同步到衍生工程时须保留各自版本（已确认保留）。
