============================================================
一、新增：心跳报文 uptime 字段（设备运行时间）
============================================================
1. 字段语义
   - 键名 "uptime"，整型，单位秒（截断取整，误差 ≤1s）
   - 取值 HAL_GetTick()/1000（TIM7 1ms 时基），开机为 0 点，约 49.7 天回绕
   - 与 device_reboot_result 报文中的 uptime 同一采样口径
2. 修改后心跳报文示例：
   {"type":"heartbeat","device_id":"...","device_status":{...},"run_status":1,
    "seq":42,"ts":1795133180,"uptime":86400,"sign":"A1B2C3D4"}
3. 代码改动（UserCode/Drivers/ETH/net_comm_task.c / .h，与主工程 2.2.6i 一致）
   - HeartBeatParam_t 新增成员 uint32_t uptime_sec
   - FillHeartBeatData()：hb_param->uptime_sec = HAL_GetTick() / 1000U;
   - tcp_send_heartbeat() 签名临时对象：在 "type" 键之后追加 "uptime" 键
     （验签原文按键名字典序，t < u，uptime 必排 type 之后）
   - tcp_send_heartbeat() 最终报文：在 "ts" 之后、"sign" 之前插入 "uptime"
4. 协议契约影响（重要）
   - 心跳 HMAC-SHA256 验签原文新增 "uptime":N，网关侧签名计算必须同步纳入该键，
     否则升级后所有心跳 sign check failed。需与网关同版本发布。

The heartbeat gains an integer-seconds "uptime" (= HAL_GetTick()/1000, zero at boot,
wraps after ~49.7 days). Struct HeartBeatParam_t adds uptime_sec; FillHeartBeatData
samples it; tcp_send_heartbeat inserts "uptime" after "type" in the signature string
(lexicographic order) and between "ts" and "sign" in the message. The gateway MUST
include "uptime" in heartbeat signature computation before deploying this firmware.
