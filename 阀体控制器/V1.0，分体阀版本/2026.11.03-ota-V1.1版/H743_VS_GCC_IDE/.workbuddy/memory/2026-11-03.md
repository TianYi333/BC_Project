## inject_running 中 waiting_met_sen 失败分支：带返回码上报具体错误点
- 文件：`UserCode/Logic/running_logic.c`（inject_running 内，约 L559-596）
- 改动：原 `if (waiting_met_sen(...) != 1)` 笼统报 `WATING_MET_SEN_FAILURE !`，改为先捕获返回值 `met_sen_ret`，按返回码 switch 生成带 n 的错误串：
  - 2=sen_id非法(>2) / 3=2s队列等待超时离线 / 4=系统总超时(>SYS_INJECT_TIMEOUT=20s) / 5=未知异常
  - 串格式 `WATING_MET_SEN_FAILURE !(n:说明)`，最长 42 字节，< `error_msg[48]` 上限，安全。
- 安全前提：`inline_report_result`(L420) 与 `record_injector_err`(L670) 均用 `strncpy` 拷贝字符串，故局部 `char met_sen_err[48]` + `snprintf` 无悬垂指针风险；`snprintf` 工程已大量使用。
- waiting_met_sen 返回码语义（备查）：1=成功，2=sen_id>2，3=2s队列超时离线，4=系统总超时，5=循环穿透未知。
- 注意：日志/OLED/上报三处均带上返回码，便于现场定位是哪种传感器失败。

## waiting_met_sen 的 sen_id 边界确认 + 错误串增强（诊断 case 3 恒超时）
- **sen_id 合法范围 = 0/1/2**，硬件只有 2 个金属传感器（SEN_1=GPIOG15/DO_INPUT_0，SEN_2=GPIOB4/DO_INPUT_1）。
  `Read_MET_Sensor()` 只在"恰好一个传感器置位"时返回 1 或 2，**两个都置位或都不置位一律返回 0**。
  `motor_loc_list[].pipe` 只会是 0/1/2，故 `if (sen_id > 2)` 的防御方向正确，保留。
- 修正了 waiting_met_sen 上方与代码不符的注释（原注释错把 0/1/2 说成"超出合法范围"，且称 pipe=0 返回 0，实际是落到 return 5）。用户选择方案 A：`sen_id==0` 维持 return 5（视为失败），不改行为。
- **case 3 恒超时 + unit_test 却能看到传感器变化** —— 根因方向已定位（unit_test 只显示 READ_MET_SEN_1/2 两个原始 GPIO 电平，从不调用 Read_MET_Sensor()，所以"引脚在跳变"≠"组合值匹配"）。
- 错误串增强（L571-587）：新增实际观测状态 `p`(期望pipe) / `g`(Read_MET_Sensor组合结果) / `r`(原始电平位 bit0=SEN_1,bit1=SEN_2)，最长 42 字节仍 < 48。
- 待现场验证的三个嫌疑点：①gpio.c 中 DO_INPUT_0 用 GPIO_PULLDOWN 而 DO_INPUT_1 用 GPIO_NOPULL（同一组 DI 上下拉不一致，DI 用 NOPULL 有悬空风险）；
  ②zdt_run_motor_loc_abs_t 只等电机 ACK 不等实际到位，waiting_met_sen 只有 2s 窗口等阀芯到位；
  ③若 r=3（两路同时置位）则组合逻辑永远得不到 1/2，需放宽 Read_MET_Sensor。

## 根因收敛：Q 电机位置零点/pipe 表与实际传感器不对应
- 排除项（已实锤）：`zdt_run_motor_loc_abs_t` 实际会等第二帧应答 buffer[1]==0x9F（到位）才返回，**电机确实到位**；用户确认 unit_test 中两传感器 0/1 交替且绝不相等 → **传感器与 Read_MET_Sensor 组合逻辑都正常**。
- 状态机链路（已推通）：Q 电机在 0°~720° 往复，每轮 +180°（id 2→4→6→8→6…，在 id 2 / id 8 处 dir 反转），开放位 pipe 依次 **1→2→1→2**；关闭位是 pipe==0 的中间位（id 1/3/5/7/9/11），由 `q_motor_run_close()` 的 id+dir*1 到达，`q_motor_run_open()` 从 pipe==0 处走 id+dir*1 进入开放位。这与用户观察到的"阀芯上下移动、两传感器交替"完全吻合 → 位置表与机械结构自洽。
- 结论：**电机到位位置上物理激活的传感器 ≠ 表里的 pipe**，即 Q 电机机械零点相对 motor_loc_list 偏移，或 pipe 表本身与本机凸轮型线不符。
- 新增诊断：`UserCode/Logic/oled_page.c` 加 `print_q_sen_map()`（static），unit_test 里 ENCODER_CW/CCW 每次移动到位后打印
  `[SENMAP] id=%d deg=%d pipe=%d -> s1=%d s2=%d g=%d OK/MISMATCH`。
  走完 0~8 号位即可得出真实映射表，据此修正 motor_loc_list[].pipe 或重新做 Q 电机归零。
- 现场条件限制：当时**未接串口**，printf 看不到 → 又加了 OLED 版诊断 `show_q_sen_map()`（static，同文件），
  在 unit_test 主循环中周期性调用（OLED 消息 4s 无刷新会自动清除，故必须循环刷新才能常驻）；
  状态栏格式 `id<位置号> p<期望pipe> s<sen1><sen2> g<组合值> OK/NG`，例 "id2 p1 s01 g2 NG"。
  `OLED_Msg.data[32]` → 最多 31 字符；屏幕 256x128，状态栏 6x10 字体约 42 字符可见，空间足够。
  printf 版本保留（`print_q_sen_map`），以后接上串口可直接看。
- 期间用户已用 CubeMX 把 DO_INPUT_1 的上下拉从 GPIO_NOPULL 改为 GPIO_PULLDOWN（与 DO_INPUT_0 一致）。
