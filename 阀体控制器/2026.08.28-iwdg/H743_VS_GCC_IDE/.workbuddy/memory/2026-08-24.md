# 2026-08-24

## injector_task 与设置模式竞态分析（running_logic.c）

- 问题：injector_task 在 SYS_MODE_STARTING 下调用 start_running()，其内部 `zdt_run_motor_loc_abs_t` 有 2×2000ms 阻塞等待、`waiting_met_sen` 阻塞 2s，期间 OLED 菜单可进入 P/Q Model Init 把 running_mode 切为 SYS_MODE_SETTING。
- 两个后果：① start_running() 结束会覆盖 running_mode（READY/STARTING 覆盖 SETTING）；② 两个任务并发向 FDCAN 下发电机命令，CAN 应答错配。
- 结论：仅"切换模式时判断"不够，需在 start_running() 每个电机操作/阻塞点前检查 `running_mode != SYS_MODE_STARTING` 则中止返回且不写模式；injector_task 侧 start_running() 返回后立即清 is_Busy，仅当 `running_mode != SYS_MODE_SETTING` 时才 vTaskDelay(2000)。
- 可选加固：设置回调入口判断 is_Busy==1 时拒绝进入（用户未选）。
- 状态：仅分析，未改代码，待用户确认方案。

## 已实施：start_running 内检查+中止（用户选定方案）

- 新增 static helper `set_mode_if_starting(_SYS_MODE mode)`：仅当 running_mode==SYS_MODE_STARTING 才写模式，被抢占不覆盖。
- start_running()：入口检查 + 每个阻塞点（P自检 / q_motor_run_point×4 / waiting_met_sen）后检查 `running_mode != SYS_MODE_STARTING` 则 return 0 中止；原 8 处 running_mode 赋值全部收敛到 helper。
- injector_task STARTING 分支：is_Busy 提前复位（start_running 返回后立即清），仅当 `running_mode != SYS_MODE_SETTING` 才 vTaskDelay(2000)，被抢占立即让位。
- 改动仅限 running_logic.c，设置回调未动（符合"仅 start_running 内检查+中止"）。
