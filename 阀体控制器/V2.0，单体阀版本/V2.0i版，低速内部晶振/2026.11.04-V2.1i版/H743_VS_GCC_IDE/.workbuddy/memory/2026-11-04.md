## 实际同步的改动清单
1. **`waiting_met_sen()` 返回值从 1/0 两档扩展为 5 档**（1成功 / 2=sen_id非法 / 3=2s队列超时 / 4=系统总超时 / 5=未知）；
   同步修正防御注释（合法 sen_id 范围固定 0/1/2；sen_id==0 落到 return 5）。
   ⚠️ 注意：衍生工程原为旧语义（1成功/0失败），**不能直接照抄主项目的调用判定**，必须同步改调用处。
2. **`start_running()` 中 `waiting_met_sen(...) > 0` → `== 1`**（bug修复：原写法把"超时"当成功，上电传感器确认实为空检查）。
3. **`inject_running()` 失败分支增强**：改用 `met_sen_ret != 1` 判定，按返回码生成 `WATING_MET_SEN_FAILURE !(n:...)` 错误串，
   并附带现场观测值 p(期望pipe) / g(Read_MET_Sensor组合值) / r(原始电平位)，OLED 显示 `sen p%u g%u r%u`，串口打印完整诊断。
4. **归零失败不再"带病启动"**：新增 `g_q_zero_ready` / `g_p_zero_ready` 全局标志（普通 .bss，掉电自动清零）；
   - 上电归零改为有限重试 `MOTOR_ZERO_MAX_RETRY=3`（间隔 500ms），成功置标志=1，仍失败保留原有 sys_warning+logInfo+OLED 告警
   - **阻断点放在绝对定位入口**：`q_motor_run_point()` / `p_motor_run_point()` 开头检查标志，为 0 直接 return 0，**不发出任何 0xFD 绝对角度指令**
   - **恢复路径**：Q/P Model Init 页手动置零（`zdt_set_motor_reset_zero`）成功后置对应标志=1，自动解除阻断
5. `running_logic.h`：新增 `MOTOR_ZERO_MAX_RETRY` 宏 + 两个标志的 extern 声明；`oled_page.c`：手动置零成功处置标志。
