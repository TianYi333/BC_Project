## "motor error ..." 仍出现的真根因 + 最终修复（running_logic.c:763，构建通过）

用户报 A+C 后 OLED 仍显示 `show_oled_msg(OLED_MSG_ERROR,"motor error ...")`。追查确认 A+C 只是止血（挡住 84/3 污染 + 索引钳 [0,11]），真根因是**反转状态机死代码**：`q_motor_run_close` 的 `switch(point.id){case 8:dir=-1; case 2:dir=+1}` 写在 `if(pipe!=0)` 内部，但 motor_loc_list 中 id=8/id=2 的 `pipe` 都是 0（关闭位）→ 到这两个 id 时函数早已 `return 1`，switch 永不进 → `dir` 恒为 +1 → 索引单调前推，第 6 次单点注油 `close_idx=11+1=12` 越界 → C 边界捕获、复位并报 motor error。与是否中止无关，确定性必现。

修复（用户选定最小方案）：把 close 的 case `8/2` 改为 `9/3`（与 open 函数已有的 `case 9/3` 一致）——id=9/3 是开放位(pipe≠0)，开关在 `if(pipe!=0)` 内可达，反转真正触发。扫描变为 id≈3↔9 来回折返，不再越界。注意：此改法稳定后扫描带 ≈id3~9，覆盖开放口 3/5/7/9（口1仅启动跑一次，口11/10 不达）；若需六口全覆盖可把反转点放到两端 id=11→-1 / id=1→+1（未做，待定）。构建通过(FLASH 67.55%)。
