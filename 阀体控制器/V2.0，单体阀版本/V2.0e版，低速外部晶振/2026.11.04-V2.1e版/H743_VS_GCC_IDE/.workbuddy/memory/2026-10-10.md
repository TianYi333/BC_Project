## 工程 CRC32 真实格式（已核实，用于定 crc 字段格式）

实现在 `UserCode/Third_Party/FlashDB/fdb_utils.c:77`：
```c
uint32_t fdb_calc_crc32(uint32_t crc, const void *buf, size_t size)
{ crc = crc ^ ~0U; while(size--) crc = crc32_table[(crc ^ *p++) & 0xFF] ^ (crc >> 8); return crc ^ ~0U; }
```
- 标准 CRC-32（IEEE 802.3 / PKZIP，poly 0x04C11DB7 反射 0xEDB88320），init=0xFFFFFFFF，末异或 0xFFFFFFFF，
  **与 `zlib.crc32()` 逐位等价**，且支持增量分块续算（`crc=0` 起调 == zlib 首调）。
- 类型 uint32_t，有效范围 1 ~ 0xFFFFFFFF（**0 视为非法**，handle 返回 -3）。
- 现有表示形式为**十进制无符号数**（upgrade_start 用 `"new_crc32":%lu`；网关脚本用 `zlib.crc32(data)&0xFFFFFFFF`）。
  cJSON Number 为 double，承载 32 位整数精确无损。→ 结论：新增 `crc` 字段建议直接沿用**十进制数值**，无需 hex 字符串。
  （注：用户最终仍选择 **8 位 HEX 字符串**，见下条，此结论仅作背景保留。）
