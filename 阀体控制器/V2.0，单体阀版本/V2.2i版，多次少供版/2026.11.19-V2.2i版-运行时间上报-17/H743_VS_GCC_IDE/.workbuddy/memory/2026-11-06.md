**关键坑（必记）**：`var_init.c:94` 把 `main_sys_status.is_Busy` 初值设为 **1**，
真实链靠 `injector_task` 的 STARTING 分支（`running_logic.c:99-101`）清零。
停用 `injector_task` 后无人复位，若只伪造 `running_mode=READY`，
`TCP_task_processing_task` 仍会以错误码 7 "The system is busy" 丢弃所有任务、`inject_task_allowed()` 恒 0。
→ **伪造就绪态必须同时清 `is_Busy`**。
采用「伪装状态」而非「注释掉三处准入判断」：`net_comm_task.c` 的验签/去重/调度/回报逻辑一行未改。

**测试任务行为（与真实链 `injector_task → inject_running` 对齐）**
- 只扫槽3；命中后置 `is_Busy=1` / `g_current_running_inj_id`，先快照 `inj_id/val/task_id/sub`。
- `task_id` 绑定校验照抄 `inline_report_result()`；`sub_index/sub_total` 取自 `g_slot3_ctx`（`valid && inj_id 匹配`）。
- 每 1mL `osDelay(pdMS_TO_TICKS(TEST_INJ_ML_DELAY_MS))`，默认 **300ms**（宏在 4169 行）；
  每次动作报 `execute_result=1, actual_volume=已完成次数`；结束报 `=2`。
- 急停 `g_force_stop_task` → `execute_result=3, error_code=3003 TaskInterrupted`（协议 V2.8 §11.2 / §3.9，
  旧死代码的自定义 200 已弃用）。
- 温湿度用 `g_sht40_*_cache`；耗时用 `HAL_GetTick()`，`valve_act_tm` 结束帧填平均耗时。
- 收尾顺序严格：`g_slot3_ctx.valid=0` → `task_object_list[3].task_status=0` → `g_current_running_inj_id=0`
  → `is_Busy=0` → 清 `g_tcp_task_bind` / `g_force_stop_task` / `g_stop_target_task_id`。
- **不写 `main_sys_status.injector[]`**（Modbus 寄存器映射），不调用任何电机/传感器驱动。
- 离线回报由 `tcp_send_execute_result()` 的 `g_tcp_connected` 守卫静默丢弃，契约离线免回报不变。
