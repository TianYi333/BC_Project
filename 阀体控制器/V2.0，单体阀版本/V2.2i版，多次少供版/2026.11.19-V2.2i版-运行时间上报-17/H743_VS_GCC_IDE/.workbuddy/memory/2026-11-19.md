## 字库原理讲解 + 给 cn_fonts.c 每个字形加中文注释（用户要求 ASCII+汉字全注释）
- 字库原理（已向用户讲解）：OLED 单色屏→字符即 0/1 点阵；只收录界面用到的 147 汉字+95 ASCII
  （GB2312 全量 6763 字要 216KB，精简后三字号合计 36.4KB）。
  离线：cn_font_gen.py 用 ctypes 调 GDI32+SimSun 取 1bpp 点阵→裁切→LSB-first+RLE 压缩→
  按 U8G2 新格式组装（23B 头+ASCII 段+4B Unicode 索引+Unicode 段）。
  运行时：SetFont→DrawUTF8 解析码点→查表定位 glyph→RLE 解码→逐像素画。
  坑：字库没有的字查不到字形；DrawStr 只按 ASCII 解码，中文必须 DrawUTF8。
- 注释实现：改 `cn_font_gen.py` 的 `emit_c()`，新增 `_split_glyphs(font)` 按记录边界切分
  （ASCII 记录 `[enc,total,gd...]`、Unicode 记录 `[hi,lo,total,gd...]`），逐字形输出并加注释：
  ASCII `/* 0x21 = 33 ! */`、Unicode `/* U+6E29 温 */`，另加段分隔注释。
  **不在 cn_fonts.c 上手改**（会自动生成覆盖），改生成器后重跑 `python cn_font_gen.py`。
- 关键校验：`_split_glyphs` 重组后与原 font **逐字节一致**（三字号全 BYTE-EXACT）；
  重生成后新 cn_fonts.c 数据行字节流与备份完全一致（37288B），cn_fonts.h 零差异；
  注释数 ASCII 285 + Unicode 441 = 242 字形×3套；UTF-8 中文注释 GCC 正常编译；
  cn_fonts.c / oled_page.c 单文件语法检查均 EXIT=0。
- 备份 `cn_font_gen.py.bak_cncomment_20261119` / `cn_fonts.c/.h.bak_cncomment_20261119`。
