# 2026-11-09 工作日志

## 分析：离线注油 150s 周期为何能在 65s 重连下触发
- 用户疑问：`adj_period_sec=150` > 心跳重连周期 ~65s，为何日志仍出现离线整轮注油。
- 结论：**150s 是"两次整轮注油之间的节流间隔"，不是"必须连续离线 150s"**。
  - `last_fire_unix` 在线收到首个 type=3 批就设（`net_comm_task.c:2840-2841`），触发后 `= now`（`:4151`），
    全程随设备 RTC 走、与在线离线无关；`due = last_fire + adj_period_sec`（`:4133`）。
  - `online` 是调度器 100ms 一拍的**瞬时快照** `g_tcp_connected==1`（原 `:4059`），
    `:4124` 离线分支**没有任何"累计离线时长"变量**；到期后只要碰到任一断连窗口（哪怕 100ms）即补注。
  - 故 65s 强制重连（`hb_lost_cnt >= HB_LOST_MAX`，`:1399-1403`）不是阻碍，而是不断提供触发机会。
- 日志时间线自洽：触发①17:16:35 → due≈17:19:05 → 17:17:35/17:18:41 两窗口跳过、
  17:19:46 窗口触发②；整轮 15×300ms+200ms≈4.7s 几乎全在断连期，
  `tcp_send_execute_result:3004` 在 `g_tcp_connected!=1` 时直接 return，故只剩末尾 2 帧可见。
- 触发①提前的原因：槽0 `new_round` 判据为 `valid==0 || task_id 变化`（`:2830`），
  日志片段非上电起点、且一直复用同一 `T-20261107-TEST01` → 走 else 分支**不重置 last_fire**，due 早过期。
  → **每轮必须换新 task_id**。
- 风险：上位机不回 `heartbeat_ack` 时每 ~65s 白送 5s `online=0` 窗口，
  即使网关全程在线也会每 150~215s 自行补整轮 = "假离线误触发"。
