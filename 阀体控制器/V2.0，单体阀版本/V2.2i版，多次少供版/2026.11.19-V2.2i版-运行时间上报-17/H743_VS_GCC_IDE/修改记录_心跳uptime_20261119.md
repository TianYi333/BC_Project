# 修改记录：心跳报文新增 uptime 字段

- 日期：2026-11-19
- 涉及模块：以太网通讯（UserCode/Drivers/ETH/net_comm_task.c / .h）
- 设备型号：LUB-CTRL-V2.0i（固件版本本次未变更，仍为 2.2.5i）

## 一、需求

心跳报文（type=heartbeat）中增加 `"uptime": 86400` 字段，上报设备自开机以来的运行时间。

## 二、字段语义

| 项 | 说明 |
| --- | --- |
| 键名 | `uptime` |
| 类型 | 整型，单位秒（秒级截断，误差 ≤1s） |
| 基准 | `HAL_GetTick() / 1000U`，TIM7 1ms 时基，开机为 0 点 |
| 回绕 | 32 位毫秒计数约 49.7 天回绕，超期后从 0 重新计 |
| 口径 | 与 device_reboot_result 报文中的 uptime 完全一致，网关可共用解析逻辑 |

## 三、改动明细

1. `net_comm_task.h` — `HeartBeatParam_t` 新增成员：
   ```c
   uint32_t uptime_sec;   // 设备运行时间(秒)：HAL_GetTick()/1000，开机计时，约49.7天回绕
   ```
2. `net_comm_task.c` — `FillHeartBeatData()`（约 1724 行）新增采样：
   ```c
   hb_param->uptime_sec = HAL_GetTick() / 1000U;
   ```
3. `net_comm_task.c` — `tcp_send_heartbeat()` 两处：
   - 签名临时对象 temp_root：在 `"type"` 键之后追加 `"uptime"` 键。字典序规则下 t < u，uptime 必须排在 type 之后，与网关按键排序算签名的规则及 device_reboot_result 的签名顺序（…ts → type → uptime）同构。
   - 最终发送报文 root：在 `"ts"` 之后、`"sign"` 之前插入 `"uptime"`。

修改后报文形如：

```json
{"type":"heartbeat","device_id":"...","device_status":{...},"run_status":1,"seq":42,"ts":1795078644,"uptime":86400,"sign":"A1B2C3D4"}
```

- 原文件备份：`_backup/net_comm_task.c.bak_hbuptime_20261119`、`_backup/net_comm_task.h.bak_hbuptime_20261119`
- 编译验证：`cmake --build build/Debug` 全量通过（241/241），链接生成 elf/hex/bin；FLASH 占用 74.98%，RAM_D1 62.78%
- 心跳数据流确认：唯一调用路径 tcp_client_task → FillHeartBeatData → tcp_send_heartbeat，uptime 发送前必被填充

## 五、兼容性与注意事项

1. **网关必须同步**：心跳验签原文新增 `"uptime":N`。网关签名计算若未同步纳入该键，设备升级后所有心跳将报 `sign check failed`。需与网关同版本发布。
2. 旧版上位机若按"接收报文键全集排序验签"实现则天然兼容；若按固定字段模板拼签名串，则需更新模板。
3. 如需连续运行超 49.7 天不重置的严格单调 uptime，可追加软件 64 位扩展（tick 回绕检测 + 高位累加），暂未实施。
