============================================================
一、新增：心跳报文 uptime 字段（设备运行时间）
============================================================
1. 字段语义
   - 键名 "uptime"，整型，单位秒（秒级截断，误差 ≤1s）
   - 取值 HAL_GetTick()/1000（TIM7 1ms 时基），开机为 0 点
   - 32 位毫秒计数约 49.7 天回绕，连续运行超期后从 0 重新计
   - 与 device_reboot_result 报文中的 uptime 同一采样口径，网关可共用解析逻辑
2. 修改后心跳报文示例：
   {"type":"heartbeat","device_id":"...","device_status":{...},"run_status":1,
    "seq":42,"ts":1795078644,"uptime":86400,"sign":"A1B2C3D4"}
3. 代码改动（UserCode/Drivers/ETH/net_comm_task.c / .h，共三处 + 结构体一处）
   - HeartBeatParam_t 新增成员 uint32_t uptime_sec
   - FillHeartBeatData()：hb_param->uptime_sec = HAL_GetTick() / 1000U;
   - tcp_send_heartbeat() 签名临时对象：在 "type" 键之后追加 "uptime" 键
     （验签原文按键名字典序，t < u，uptime 必排 type 之后，与 device_reboot_result
      的签名顺序 …ts → type → uptime 同构）
   - tcp_send_heartbeat() 最终报文：在 "ts" 之后、"sign" 之前插入 "uptime"
4. 协议契约影响（重要）
   - 心跳 HMAC-SHA256 验签原文新增了 "uptime":N。网关侧签名计算必须同步纳入该键，
     否则设备升级后所有心跳将报 sign check failed。需与网关同版本发布。
   - 旧版上位机若按"接收报文键全集排序验签"实现则天然兼容；若按固定字段模板拼串，
     则需更新模板。
5. 未做（可选后续）：如需连续运行超 49.7 天严格单调的 uptime，可在固件追加
   tick 回绕检测 + 高位累加的 64 位软件扩展（约 10 行），本版未实施。

The heartbeat message gains an integer-seconds "uptime" field (= HAL_GetTick()/1000,
zero at boot, wraps after ~49.7 days, same sampling basis as the uptime in
device_reboot_result). The struct HeartBeatParam_t adds uint32_t uptime_sec,
FillHeartBeatData() samples it, and tcp_send_heartbeat() inserts "uptime" both into the
signature temp object right after "type" (lexicographic order, t < u, mirroring
device_reboot_result) and into the final message between "ts" and "sign".
IMPORTANT: the gateway must include "uptime" when computing/verifying the heartbeat
HMAC, otherwise every heartbeat will fail the sign check after the upgrade; ship the
firmware and the gateway together. A 64-bit monotonic uptime extension for the
49.7-day wrap is intentionally not implemented in this release.
