## OLED 中文显示可行性与自建精简字库（用户选：方案 A + 全部文案 + 3 套字号 + 本轮只生成字库文件）
- 只读盘点结论：**可以中文显示**。屏幕 = SSD1363 256×128 单色 OLED（硬件 SPI2，
  `oled_u8g2.c:70` 的 `u8g2_Setup_ssd1363_256x128_f`，全缓冲 4096 B）；界面在

- **卡点**：现全部用 `u8g2_DrawStr()`，底层是 `u8x8_ascii_next` **单字节 ASCII 解码**，
  中文 UTF-8 会逐字节变乱码；且实际链接进 ELF 的只有 5 个 ASCII 字体
  （`6x10_tf`/`9x15_tf`/`ncenB12_tr`/`ncenB14_tr`/`ncenB18_tr`，约 11 KB）。
  `-fdata-sections` + `--gc-sections` 会回收未引用的 `u8g2_fonts.c`（38 MB / 2039 字体）。
  中文必须改 `u8g2_DrawUTF8()` + `u8g2_GetUTF8Width()`（`u8g2_font.c:1061`、`u8g2.h:973`）。
- U8G2 自带 `wqy12..16_t_chinese1/2/3`、`gb2312`、`unifont_t_chinese*`；**最大只有 16 px**，
  24 px 无现成点阵。本机有 SimSun/msyh TTF，但 Python 无 Pillow/fontTools，
  PowerShell `Add-Type` 被安全策略拦 → 改用 **ctypes 调 GDI32 在 1bpp 位图上 TextOutW 取模**
  （零依赖、零联网；宋体 12/16 px 有内嵌点阵，比轮廓缩放清晰）。
- 新增 3 个文件（均在 `UserCode/Drivers/Oled/`，CMakeLists GLOB 与 include 路径**原本就覆盖**，无需改）：
  `cn_font_gen.py`（生成器 + 内置解码器 + 文案清单 `TEXT_TABLE`）、`cn_fonts.c`、`cn_fonts.h`。
  字库为 **U8G2 原生字体格式**（23 B 头 + ASCII 段 + Unicode 查找表 + Unicode 段，
  LSB-first 位域 + (0游程,1游程,continue) RLE），可 `u8g2_SetFont(&g_u8g2, cn_font_16)` 直接用。
  每套含 ASCII 0x20-0x7E (95) + 界面中文/标点 147 = 242 字形；汉字固定全宽，ASCII 变宽。
  体积：12×12 **9270 B**、16×16 **11790 B**、24×24 **16228 B**，合计 **36.4 KB**。
- **格式要点（复用价值高）**：`start_pos_upper_A/lower_a` 是相对 offset 23 的偏移；
  `start_pos_unicode` = ASCII 段总长（含 `[0][0]` 终止），指向查找表；查找表可用单项
  `[delta=4][e=0xFFFF]` 让 do-while 立即退出；Unicode 记录 `[enc_hi][enc_lo][size][data]`，
  `size = 3 + len(data)`，ASCII 记录 `size = 2 + len(data)`，**均须 ≤255**。
  官方字体的 glyph_data 末尾**无 padding**，解码读 `ptr+1` 会跨进下一条记录（C 里合法）；
  本项目生成的 glyph_data 自带 2 个 0 padding，**不依赖相邻记录**，更稳。
