## 离线周期整批注油（覆盖"整轮都发生在离线期"的后续轮次）—— 2026-10-29 最终实现
- 用户澄清（最终模型）：
  1. **单帧单批**：每个 `task_order` 仅 1 个 `task_info`（一批=一帧），分批逐帧下发。
  2. **离线策略**：`total_x10=15/sub_total=5/inj_v=3` 为例——在线已注到第3批后断连，未收到的第4、5批**不注**（自然满足：无表项即不触发）；之后**按 `adj_period_sec` 间隔，每轮自行整批注 `total_x10=15`**，且离线不回报结果。
- 缺口：现有 g_sched_list 离线分支**仅覆盖"本轮已收批在离线态到达 exec_at"**；若一整轮都发生在离线期（收不到任何批），`g_sched_list` 无该轮表项、调度器不触发 → 离线期后续轮次完全不注油。
- 实现（用户确认"实现" + 参考时刻取"本轮首批发时间"）：
  - 新增结构体 `OfflineRoundSched_t` + 全局 `g_offline_round_sched`（net_comm_task.h / .c:51）。
  - 捕获点：`tcp_parse_cmd` 的 `task_type==3` 分支——首次见到该 task_id = 新一轮，记 `{task_id,inj_id,total_x10,adj_period_sec,last_fire_unix(=首批发 exec_at 或 now)}`；同轮后续批刷新配置；迟到的 `sub_index==1` 用其 exec_at 校正轮起点。
  - 触发点：`task_scheduler_task` 离线分支（g_sched_list 循环之后）新增判定 `!online && valid && adj_period_sec>0 && total_x10>0 && 槽3空闲` 且 `now>=last_fire_unix+adj_period_sec` → 置 `task_object_list[3].val=total_x10; task_status=1`（不写 g_sched_list、不回显 sub、`g_tcp_connected` 守卫使回报被丢弃），随后 `last_fire_unix=now` 防同轮重注/爆发补注。
  - 与 g_sched_list 离线分支互补：前者管"本轮"、本机制管"后续整轮"；在线恢复即自动停（仅 offline 触发）。
- 编译：`build/verify` EXIT=0，FLASH 359932 B。
- 文档 `供油策略阀体待实现功能说明(1).md`：§4.2 新增能力 #9；§6 新增 #9（离线周期整批注油机制，含"单帧单批"使用习惯）。
- MEMORY.md 供油契约段：补离线周期机制 + "单帧单批"使用习惯。
