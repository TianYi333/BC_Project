## execute_result 上报细化（用户二次澄清）
- 用户澄清：sub_index/sub_total 若回报须等于 task_order 下发的同名字段；并定"仅 type3（分次）回显"，非分次(1/2/4)不回报；period_seq 属网关侧轮次、设备仍不回传。
- 用户追加：execute_result 的 task_info 须**必带 task_type**（1=手动/2=周期/3=分次/4=伺服），原样回显下发值。
- 实现：
  1. net_comm_task.h：g_tcp_task_bind 与 ExecuteResultInfo_t 各加 task_type 字段。
  2. net_comm_task.c：队列消费(:3317)、调度器在线(:3783)、离线(:3823) 三处给 g_tcp_task_bind.task_type 赋值（来源 p->task_type / s->task_type）。
  3. running_logic.c inline_report_result：exec_info.task_type = g_tcp_task_bind.task_type；重新加回 g_slot3_ctx 读取块（仅填 sub_index/sub_total，不含 period_seq）。
  4. net_comm_task.c tcp_send_execute_result：task_type 常驻输出；sub_index/sub_total 仅 sub_total>0（即 type3）时输出；period_seq 不输出。
- 死代码 test_oil_filling_task 的 sim 上报块维持已清理状态（不回 sub/task_type），该函数已禁用，不影响线上。
- ExecuteResultInfo_t 的 period_seq 字段仍保留（未用）；g_slot3_ctx.period_seq 仍由调度器写入但不再上报。

## 契约澄清：三字段值均须来自 task_order 的 task_info（用户三次澄清）
- 用户明确：task_type / sub_index / sub_total 三个回报字段的值**必须原样来源于 "task_order" 下发的 task_info**，不允许设备自造值。
- 追溯确认：
  - task_type：队列消费(:3317)、调度器在线(:3783)、离线(:3823) 三处均由 p->task_type / s->task_type（下行）赋值 → 全合规。
  - sub_index/sub_total：在线 type3 由 s->sub_index/s->sub_total（下行）回填 → 合规；
    但**离线 type3 分支原把两字段强制填 0（设备自造值，违反澄清）** → 已修复。
- 修复（用户拍板"离线不回显"）：net_comm_task.c 离线分支(:3825-3828) 删除 g_slot3_ctx.valid=1 及 sub_index/sub_total/period_seq=0 整块，
  改为仅 `memset(&g_slot3_ctx,0,...)`（valid 保持 0，inline_report_result 跳过分次字段）；task_type 仍由 g_tcp_task_bind.task_type=s->task_type 回显。
  即：离线整轮注油不再带 sub_index/sub_total（设备无状态，契约 §3.2 允许省略），避免"整轮注完却报单份序号"误导网关。
- 防泄漏已验证：injector_task 的 READY(:154)/MONITOR(:179) 两条路径任务结束均 g_slot3_ctx.valid=0 清零，正常流程不会把上一份 type3 的 sub_* 泄漏给下个非分次任务。
- 编译验证：`build/verify` 增量 `cmake --build` EXIT 0，FLASH 359596 B。
- 最终规则：task_type 全路径必带且来自下行；sub_index/sub_total 仅在线 type3（sub_total>0）回显且值=下行同名字段；离线 type3 与所有非分次均不带分次字段；period_seq 始终不回报。
