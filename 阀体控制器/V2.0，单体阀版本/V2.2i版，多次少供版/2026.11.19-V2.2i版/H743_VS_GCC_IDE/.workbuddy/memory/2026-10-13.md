- 用户最终确认：之前升级后卡在 `[BOOT] verify ok / meta=2 written` 乃至 `[BOOT] HARDFAULT`
  (HFSR=0x40000000, CFSR=0x00008200 PRECISERR, BFAR=MMFAR=0x08100000, PC=0) 的根因是

  - `Core/Src/rtc.c:111`：`RTCClockSelection = RCC_RTCCLKSOURCE_LSI`

## 2. 本版本补回 CLOSE_WAIT 修复（此前缺失）+ 双连接根因修正
- 核查发现 `UserCode/Drivers/ETH/net_comm_task.c` 的 `tcp_recv_cb` 关闭分支仍是**旧版 bug**：
  无条件 `tcp_pcb = NULL`。该逻辑在**对端优雅 FIN**场景（`p==NULL, err==ERR_OK`）下会留下
  CLOSE_WAIT 孤儿 pcb（`safe_tcp_close()` 在 tcp_pcb==NULL 时跳过），属**潜在**隐患。
- 已重新落修复：仅当 `err != ERR_OK` 时清空 `tcp_pcb`（lwIP 自释放）；优雅 FIN 时故意保留
  `tcp_pcb`，交主循环 `safe_tcp_close()` 真正关闭。属**防御性修复**，逻辑自洽、无 UAF。
- ⚠️ **认知修正（用户提供关键反证）**：用户指出“没改前也只有一个连接”。
  说明双连接的真实根因**不是**这个 CLOSE_WAIT 僵尸，而是 **LSE 版卡死→复位残留**：
  `HAL_NVIC_SystemReset` 不向对端发 FIN/RST，PC 侧 TCP 保留旧半开连接，设备重启建新连接
  → PC 侧看到“多个连接”。这是 PC 侧连接表残留，非设备协议栈僵尸。
- 结论：CLOSE_WAIT 修复可保留（修真实隐患、无副作用），但非之前双连接主因；当前单连接 =
  测试未触发 FIN 路径 + LSI 稳定无复位残留。
- `reject_fname`（`ota.c:178/183`）本版本已在，无需改动。
- 用户授权语：“将上面修改在这个版本上重新修改一下”。

## 3. 网络配置存外部 Flash（关键排查认知）
- 现象：擦除**内部 Flash**（0x08000000 起扇区）后重新下载，设备上电仍是旧静态 IP，不进入自动链路 IP(AutoIP)。
- 根因：网络配置不存在内部 Flash，而存在**外部 W25Q64 SPI Flash** 的 FlashDB 分区。
  - `fal_cfg.h` 分区表（全部在 `norflash0`＝外部 SPI Flash）：
    `ef_kvdb1`@0/64KB、`ef_kvdb2`@64KB/64KB、`ef_kvdb3`@128KB/64KB、
    `firmware_a`@192KB/1MB、`firmware_bak`@1216KB/1MB、`ota_meta`@2240KB/64KB。
  - `net_comm_task.c:171 net_config_init()`：上电从 `net_kvdb` 读 key `net_cfg`；
    若 `len==sizeof(NetConfig_t) && configured==1` → 用保存 IP 并 `autoip_stop()`；
    否则 → `autoip_start()`（自动链路 IP）。
  - `net_config_save()`(232) 配网时把 `g_net_cfg.configured=1` 写入 FlashDB。
- 结论/解法：要恢复 AutoIP，必须擦**外部 Flash**（STM32CubeProgrammer 的 "Erase external memory" 页），
  擦 0x0~0x2FFFF（前 192KB＝三个 kvdb 分区）即可清除 `net_cfg`，且不影响 OTA 固件备份；
  仅擦内部 Flash 永远无效。

## 4. "TCP clear 0 pending send msg" 每 ~600ms 刷屏根因
- 现象：串口连续打印 `[NET:1176] TCP clear 0 pending send msg`，约 600ms 一条。
- 根因：该行是 `safe_tcp_close()` 末尾 `LOG_NET("TCP clear %lu ...", drop_count)`（line 1176），
  无条件打印；`drop_count=0` 表示发送队列本就为空。
- 触发链：处于 **AutoIP 模式**（`g_network_configured==0`，即上一步擦外部 Flash 配置后）
  → 主循环 `tcp_client_task` 的 `if(g_network_configured==0){ safe_tcp_close(); osDelay(500); }`
  （line 1209-1216）每 500ms 调一次 `safe_tcp_close()`；此时 `tcp_pcb` 早已 NULL、队列空
  → 每次都走末尾打印 → 加函数内 vTaskDelay(20) 等开销 ≈ 600ms 一条。
- 性质：**日志噪音 + 设计冗余，非故障**。AutoIP 模式只做 UDP 广播发现、不连 TCP。
  重新配网写回 `net_cfg`（`configured==1`）后该分支不再进入，刷屏停止。
- 可选修复（用户未授权，待确认）：A) 1176 行改为仅 `drop_count>0` 时打印；
  B) 1214 分支加 `tcp_pcb!=NULL || 队列非空` 判断再调 `safe_tcp_close()`。
