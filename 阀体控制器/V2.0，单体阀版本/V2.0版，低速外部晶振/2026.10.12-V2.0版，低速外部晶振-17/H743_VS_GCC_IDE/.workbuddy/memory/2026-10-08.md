## RTC 掉电不保存时间（用户加电池后仍丢）——诊断
- 用户问：加了电池，断电重启屏幕仍从原始值开始（时间没保留）。
- 软件层已确认**无误**：
  - `rtc.c:59-70` `MX_RTC_Init` 有 `RTC_ISR_INITS` 判断：已初始化则 return，不重写时间（保留逻辑正确）。
  - `UserCode/Drivers/Clock/rtc_cluck.c` 的 `UnixMs_To_RTC`/`Unix_To_Time`（SetTime/SetDate）仅在用户**主动设时间**时调用，不在启动跑。
  - 所以“回到原始值”= 默认分支执行 = 启动时 `INITS==0` = **备份域被复位**。
- 根因（高概率）= **硬件 VBAT 没真正保住备份域**：H7 的 RTC+备份寄存器+LSE 都在备份域，只由 **VBAT 引脚** 供电；VDD 掉电后只有 VBAT 还供着才不丢。电池没接对位置/没供上 VBAT 就会每次断电复位。
- 板级高概率原因：① VBAT 被板上 0Ω/跳线接到 VDD（拔 VDD 备份域也断电）；② 电池座没连到 MCU VBAT 引脚；③ 电池没电/<1.8V（H7 不切 VBAT）；④ VBAT SEL 跳线在 VDD 档。
- 决定性排查（万用表，断电后）：量 MCU **VBAT 引脚**对 GND 电压，≈0V/<1.8V 即实锤；量 VBAT 与 3.3V 间电阻≈0Ω 即被接到 VDD。
- HAL 行为确认（`hal_rtc.c:319` `__HAL_RTC_IS_CALENDAR_INITIALIZED` + 退出 init 模式后置 INITS=1）：用 `INITS` 判断有坑——备份域一旦复位，HAL_RTC_Init 重初始化并把 INITS 置 1，致 `if(INITS) return` 恒真，`rtc.c:72-91` 的 2025-01-01 默认**永不会执行**（复位后显示硬件默认 2000-01-01）。CubeMX 标准做法是用备份寄存器 `HAL_RTCEx_BKUPRead/Write(RTC_BKP_DR1,0x32F2)` 判断。此坑仅影响“无电池时的默认显示”，**不影响真正保留——保留只能靠 VBAT**。
- 关联：当天刚把 RTC 源 LSI→LSE；LSE 晶振在备份域靠 VBAT 维持。第一次切 RTCSEL 会清一次备份域（一次性丢），每次都丢才是 VBAT 问题。
- 待用户：用万用表确认 VBAT 电压；是否要把 INITS 判断改为备份寄存器判断（先确认再改）。

### 逐行查证“程序是否每次启动复位 RTC”（用户质疑“与程序有关吗”）
- 全工程 grep `BACKUPRESET/BDRST`：仅 `hal_rcc_ex.c:918-919` 一处 `__HAL_RCC_BACKUPRESET_FORCE/RELEASE`。
- 该处位于 `HAL_RCCEx_PeriphCLKConfig` 的 RTC 分支（hal_rcc_ex.c:889-956），**且仅当** `RCC->BDCR.RTCSEL != 请求的RTCSEL` 时才复位备份域（line 913 判断）。VBAT 正常时 BDCR 被保留=RTCSEL=LSE，不触发 → **正常启动不会清备份域**。
- `HAL_RTC_Init`(hal_rtc.c:319)：仅当 `INITS==0` 才进 init 模式；VBAT 保留时 INITS=1，跳过。
- `MX_RTC_Init`(rtc.c:65)：`if(INITS) return;` 已初始化即跳过默认时间。
- `SystemClock_Config`：HAL_RCC_OscConfig(LSEON) / LSEDRIVE_CONFIG 均不复位备份域。
- main.c 启动序：HAL_Init→SystemClock_Config(107)→PeriphCommonClock_Config(110)→…→MX_RTC_Init(122)，无额外复位。
- **结论：程序侧干净，没有任何“每次启动都复位 RTC”的路径。时间不保留的唯一触发条件是“备份域真的断电(VBAT 没供上)”。**
- 给用户的“一锤定音实验”：设好时间后**只按 NRST 复位、不断 VDD**——若时间保留→程序与备份域硬件均正常→之前丢失 100% 是 VBAT 在断 VDD 时没供上(纯硬件)；若 NRST 也丢→才是真有复位 bug(按上面分析概率极低)。注意：重新下载/ST-Link 连跑常伴随系统复位或 mass erase，不算有效保留测试。
