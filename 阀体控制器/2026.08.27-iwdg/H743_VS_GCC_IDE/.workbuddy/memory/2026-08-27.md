## TCP 安全关闭逻辑改造（net_comm_task.c，参考外部代码）

按参考代码的安全处理逻辑修改了 5 处，工程 ninja 增量构建通过（FLASH 63.77%）：

1. `safe_tcp_close()`：改为先 `LOCK_TCPIP_CORE()` 再拿 `tcp_send_mutex`（锁序 core→mutex）；关闭策略从直接 `tcp_abort` 改为"先清全局指针→`tcp_close` 优雅关闭→失败回退 `tcp_abort`"；发送队列清空和 vTaskDelay(20) 移出 do-while 与核心锁外。保留工程特有的 `xQueueReset(xTimerReqQueue)`。
2. `tcp_client_task` 重连段：PCB 创建/连接包在 `LOCK_TCPIP_CORE` 内；原 `if(tcp_pcb != NULL) safe_tcp_close()` 改为 UNLOCK+continue（持核心锁时再调 safe_tcp_close 会死锁）；tcp_connect 失败分支 `tcp_close`→`tcp_abort`（SYN_SENT 下 tcp_close 可能 ERR_MEM 失败）。
3. `tcp_error_callback`：新增清 `tcp_pcb=NULL`、`g_tcp_connected=0`（errf 返回后 lwIP 立即释放 pcb，防 UAF/HardFault）。
4. `tcp_connected_cb` 失败分支：删除回调内 `tcp_abort(tpcb)`（pcb 所有权归 lwIP），仅清全局引用，由 errf 释放。
5. `tcp_recv_cb` 错误分支：新增清 `tcp_pcb=NULL`、`g_tcp_connected=0`（防 UAF）。

未改动（与参考代码的差异属工程设计，非安全问题）：心跳经 xTimerReqQueue 发送（参考为直接调 tcp_send_heartbeat）；LOG_NET 宏不存在，沿用 LOG；tcp_sender_task 只持 mutex 不持 core 锁（与 safe_tcp_close 锁序不冲突）。

后续：删除了 tcp_client_task 内的 `static uint32_t reconnect_tick` 局部变量，解除对文件级全局（21 行）的遮蔽。删除后行为变化（均为原本被遮蔽弄失效的正确意图）：1023 行配网 IP 变更写 `reconnect_tick = HAL_GetTick()-5000`（立即重连）与 1352 行握手失败回调写 `HAL_GetTick()`（失败后 5s 节流）现在真正生效。ninja 构建通过。

再修正：删除遮蔽后复核发现"IP 变更立即重连"仍不生效——1023 行回拨的 reconnect_tick 会被 tcp_client_task 的 pending-close 分支（1194 行 `reconnect_tick = HAL_GetTick()`）覆盖。修复：新增文件级 `static volatile uint8_t g_fast_reconnect`，1023 行置 1，重连门判断加 `&& (g_fast_reconnect == 0)`，通过门后清零消费。握手失败 5s 节流确认已生效。ninja 构建通过。
