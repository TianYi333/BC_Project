## 以太网通讯模块代码审计（net_comm_task.c）
目标：排查内存泄露与严重 bug。

结论摘要：
- **未发现活跃的堆内存泄露**。所有动态分配路径（pvPortMalloc 发送缓冲、pbuf、cJSON 对象/字符串）在所有 trace 路径上均被正确释放：
  - tcp_sender_task 在每个分支释放 msg.data；safe_tcp_close 排空发送队列并释放；tcp_write 用 TCP_WRITE_FLAG_COPY，释放安全。
  - cJSON_Delete / cJSON_PortFree 在 exit 路径全部配对。

严重 bug：
1. **[严重] tcp_recv_cb (L1347-1365) 未处理分片 pbuf 链**：只拷贝 p->len（首段），`tcp_recved(tpcb, p->len)` 应传 p->tot_len。链式 pbuf 时尾部数据丢失 + 接收窗口少报 → 对端停发、连接假死。单段报文时巧合正确。
2. **[隐患] udp_send_device_online (L705-710) 提前 return 未释放 udp_pcb_mutex**：当前被递归锁 + 调用方兜底释放掩盖，但函数自身加锁未配对释放，属潜在死锁/契约错误。
3. **[健壮性] tcp_recv_cb 在 lwIP tcpip 线程内做 cJSON 解析+HMAC+可能 sync_to_sysdb 写 Flash**：阻塞网络线程，有栈溢出/超时风险。
4. **[安全] 重放防护被注释**：udp discover/config_set 与 tcp_parse_cmd 中 time/seq 校验的 goto 被注释（L773/779、L935/942、L1956/1962），时序与序列号校验形同虚设。

审计者备注：建议后续修复上述 1、2、4 项。mutex 均为递归锁（freertos.c L188-203）。

## HardFault 根因分析（用户截图）
- 现象：Udp_discover_task → udp_msg_process → pbuf_alloc → memp_malloc → mem_malloc → _malloc_r 时触发 HardFault。
- 寄存器：HFSR FORCED=1；CFSR=0x8200（BFARVALID + PRECISERR）；BFAR=0xFFFFFFFC。
- 根因：lwIP 配置了 `MEM_LIBC_MALLOC=1` 和 `MEMP_MEM_MALLOC=1`，pbuf/memp 全走 newlib-nano malloc/free；但 newlib-nano 默认 `__malloc_lock`/`__malloc_unlock` 是空桩，libc malloc 在多任务并发下不线程安全，堆空闲链表被踩坏，最终 `_malloc_r` 解引用损坏的 next 指针（0xFFFFFFFC）触发精确总线错误。
- 修复：在 `Core/Src/sysmem.c` 中重载 `__malloc_lock`/`__malloc_unlock`，使用 FreeRTOS 递归互斥锁保护 newlib 堆。调度器启动前（单上下文）跳过加锁；首次 malloc 时临界区懒加载静态递归锁。
- 注意：此问题与前面修改的 TCP/UDP 代码无关；是独立的系统性并发缺陷。

## 看门狗频繁重启根因 + 方案A修复
- 现象：加 malloc 锁 + 开看门狗 + 频繁收发 → 喂狗任务被阻塞 → 频繁重启；关掉 MX_IWDG1_Init 后可正常运行。
- 根因（非看门狗任务本身问题）：IWDG 窗口约 512ms（Prescaler_4, Reload 4095, LSI≈32kHz）；IWDGTask 原 `osPriorityHigh`(映射 FreeRTOS 39)。而 `ethernetif.c` 的 EthIf 收包任务为 `osPriorityRealtime`(48)，优先级高于喂狗任务。加锁后 lwIP 每个 pbuf 分配都走 malloc 互斥锁，频繁收发时高优先级 EthIf 长时间占 CPU（且优先级继承会把低优先级分配者临时抬到 48 以上），把喂狗任务饿死超过 512ms → 复位。
- 关键坑：本工程 CMSIS-RTOS2 包装层（cmsis_os2.c L465）把 `osPriority_t` **直接**当 FreeRTOS 优先级，无偏移；`configMAX_PRIORITIES=56` → 合法优先级 0..55。`osPriorityISR=56` 会越界，不可用。
- **修复（方案A）**：`freertos.c` IWDGTask_attributes.priority 改为 `osPriorityRealtime7`(=55)，既 <56 合法、又 >48 高于 EthIf，保证喂狗任务总能抢占。喂狗任务仅 refresh+delay 不 malloc，抬到最高不影响其它任务。
- 待办（方案B，治本）：将 lwipopts.h 的 `MEM_LIBC_MALLOC`/`MEMP_MEM_MALLOC` 改为 0，让 lwIP 用自己的静态堆（0x30000800, MEM_SIZE 65535），pbuf 分配不再走 newlib malloc 锁，从根上消除热路径锁竞争。改动面较大，需重建验证内存余量。

## 方案A 不足 + 方案B 落实（用户：UDP 100ms 仍频繁重启）
- 用户实测：方案A（喂狗抬到 55）后，UDP 100ms 频率仍频繁重启；关看门狗则"正常跑"。
- 关键推理：`osThreadNew`(cmsis_os2.c L468) 仅拒绝 `prio > osPriorityISR(56)`，55 合法 → 喂狗任务确为最高优先级 55。最高优先级任务只做 refresh+delay，**不可能被任何任务饿死**。故重启不是纯任务抢占，而是 CPU 卡在更高特权上下文（HardFault/ISR 死循环），导致 55 级喂狗任务也跑不起来；而无看门狗时该偶发堆损坏 HardFault 只是静默死机，不易察觉。
- 真正的根：lwIP 仍把全部 pbuf/memp 分配走 newlib malloc + 任务互斥锁这条脆弱链路（并发堆损坏/锁竞争/优先级继承）。方案A 没动这条链路，故未治本。
- **方案B 已落实（LWIP/Target/lwipopts.h，写在 USER CODE BEGIN 1 以便 CubeMX 重生成保留）**：
  - `#undef/#define MEM_LIBC_MALLOC 0`、`MEMP_MEM_MALLOC 0`：lwIP 改用自身静态堆（受 SYS_LIGHTWEIGHT_PROT 保护），彻底脱离 newlib malloc 热路径。
  - `LWIP_RAM_HEAP_POINTER` 由 `0x30000800` 改为 `0x30034000`：原指针与 `.Rx_PoolSection`（RX_POOL，128×~1576B≈197KB，约 0x30000100–0x30031E00）重叠；RAM_D2 末端 0x30048000，0x30034000+MEM_SIZE(65535)=0x30044000 留 16KB 余量，安全。
  - `SYS_LIGHTWEIGHT_PROT 1`：opt.h 默认已是 1；注意 ST 移植 sys_arch.c 的 sys_arch_protect 实际用 `lwip_sys_mutex`（任务互斥锁）而非临界段，故 LWIP_ALLOW_MEM_FREE_FROM_OTHER_CONTEXT=1 严格说并非 ISR 安全——但本工程 pbuf_free 均在任务上下文（ethernetif_input / low_level_output / HAL_ETH_TxFreeCallback 经 ReleaseTxPacket 任务调用），无 ISR 释放，故当前无害。
- 保留 `Core/Src/sysmem.c` 的 newlib malloc 锁：仅覆盖应用层 malloc（cJSON 等用 pvPortMalloc 不走它；其余 C 库偶发 malloc 频率极低），不再参与 lwIP 热路径，无看门狗风险。
- 方案A 的 IWDG=55 保留（看门狗本就不应被饿死），可不动；根因修好后非必须。
- 待办/注意：若后续做重 TCP 吞吐，64KB 堆(MEM_SIZE)可能偏紧（TCP_SND_BUF/WND 各 16KB），可上调 MEM_SIZE 并相应上移堆指针（切勿与 RX_POOL 重叠）。建议用户重建并做 UDP/TCP 压力复测。

## 实现 debug_pid_tune_callback（PID 在线整定，方案1）
- 文件：`UserCode/Logic/oled_page.c` `debug_pid_tune_callback`（原占位 "Function Not Implemented"）。
- 关键机制（已核实）：`PressureControlTask` 每周期 `cfg_tmp = sys_cfg` 直接读 `pid_kp/ki/kd` → 改写全局 `sys_cfg` 三个增益即**实时生效**（不依赖 Flash）。`sync_to_sysdb()` 写 FlashDB。
- 设计：
  - **不强制进入 SYS_STATE_SETTING**（原占位代码会进 SETTING 旁路闭环，看不到整定效果）。保留进入前状态；若已在 PRESS/HOLD 闭环运行，调参即时可见。
  - 短按 ENCODER_PUTH = 切换选中 Kp/Ki/Kd（sel_idx 0/1/2）；旋转时实时写 `sys_cfg` 三增益。
  - 长按 ENCODER_PUTH_LONG = 落盘 `sync_to_sysdb()` 并退出，避免高频 Flash 写。
  - 顶部标题 "PID Auto Tune"；三行 Kp/Ki/Kd 高亮当前行；底部单行遥测 `Ref/P/E/R/RPM + LIVE|OFF`（LIVE=闭环在跑，OFF=不在 PRESS/HOLD）。
