## 审查：TCP 连接多链路 + 心跳/重连逻辑
- 结论：工程**不存在**对服务端的多余连接链路。
  - 单一全局 `tcp_pcb`，全工程仅 1 处 `tcp_new`/`tcp_connect`（net_comm_task.c:1266/1279，均在 `Tcp_client_task`）。
  - 重连块二次防护 `if(tcp_pcb != NULL){UNLOCK;continue;}`（1261）防重复建链；所有断连路径（safe_tcp_close/tcp_error_callback/tcp_recv_cb错误/tcp_connected_cb失败）均先清空并释放旧 pcb。
  - tcp_send_register/心跳/应答均复用同一 pcb + tcp_send_queue 异步发送，不开第二链路。
- 心跳/重连逻辑问题（3 点，未改代码）：
  1. 【关键耦合】`hb_lost_cnt` 仅在任何服务器有效签名报文验签通过时复位（tcp_parse_cmd:2222），即"链路存活"依赖服务器下发而非 TCP 本身。若服务器纯单向不回包，健康连接约 60s（3×20s，HB_LOST_MAX=2）后被强制断开 → 潜在误杀。需与服务器协议核对；若无回执应改为按"发送成功"复位或启用 lwIP 原生 keepalive。
  2. 【注释过期】HEARTBEAT_PERIOD_MS 注释"30s"实为 20000(20s)；HB_LOST_MAX 注释"累计3次"实为 2；1210 行注释"累计3次"矛盾。
  3. 【边缘】hb_lost_cnt++ 在发送前递增，心跳队列满被丢弃时仍 +1（风险极小）；实际断开在第 3 周期（>=2）触发。
- 重连节流路径正确（g_fast_reconnect + 全局 reconnect_tick + 5s 节流兜底，无重试风暴）。
- 锁序：safe_tcp_close 取 core→tcp_send_mutex；connected_cb 在 tcpip 线程内已持 core 再取 mutex，顺序一致无死锁。

## 排查：初次上电首次进入菜单需长按两次
- 现象：设备初次上电后，第一次"进入菜单页面"需要长按两次。
- 定位根因：`oled_task.c:76` 上电后**无条件**调用 `home_page_callback()`（oled_page.c:2666）。该函数显示温湿度页(Home Page)后 `while(!long_pressed)` **阻塞**等待 `ENCODER_PUTH_LONG` 才返回。
  - 因此上电后设备先停在"温湿度首页"，用户须**长按一次**退出 Home Page，主循环(oled_task.c:93)才显示主菜单列表。
  - "两次"推测 = ①长按退出 Home Page 进主菜单；②再在顶层选某项进入二级菜单（顶层长按=BACK 无效，需短按 ENTER），被用户统归为"进入菜单要按两次"。
- 超时回首页路径(oled_task.c:89)同样调 `home_page_callback()` 阻塞等长按，机制一致。
- 未改代码；修复方向取决于设计意图（上电默认显示主菜单列表 vs 温湿度首页），待用户确认。

## 修正：上电首次"长按两次"的根因（替代前述"退出Home Page+进二级菜单"的推测）
- 经查 `Encoder.c:36-38`：`static uint8_t lastA=0; lastB=0; lastP=0;` 初始值与实际空闲电平不符。
- `gpio.c:122-126` `EC11_P_Pin` = `GPIO_MODE_IT_RISING_FALLING` + `GPIO_NOPULL`（无内部上下拉，依赖外部上拉→空闲高=1）。
  - 故 `lastP=0` 与空闲高(1)不一致。上电后第一次按钮按下（下降沿 currentP=0, lastP=0）：`lastP==1 && currentP==0` 不成立 → **漏检，不记录按下**；第一次松开也无事件发出 → `home_page_callback`(只认 PUSH_LONG) 不退出，仍停温湿度页。
  - 第二次按下时 lastP 已被第一次松开同步为1 → 正常识别 → 长按释放发 PUSH_LONG → 退出 Home Page 进主菜单。正好对应"初次上电第一次需长按两次"。
  - 即便外部为下拉(空闲低)，`lastP=0` 虽与空闲一致，但按下(上升沿)被代码误判为"释放"分支，`button_pressed` 不置位 → 首次操作同样异常。故根因是 `lastA/lastB/lastP` 初始未与实际引脚电平同步。
- 修复方向（已实施）：把 `lastA/lastB/lastP` 提升为文件级 static，新增 `Encoder_SyncInitialLevel()` 读取三引脚当前实际电平并置 `g_encoder_synced=1`；`OLED_Task_Entry`（oled_task.c:76）进入 `home_page_callback()` 前调用一次；回调开头 `if(g_encoder_synced==0)` 兜底同步并 `return` 丢弃首中断。因启动期已先同步，`g_encoder_synced` 在用户操作前即为 1，兜底 `return` 不会丢弃真实按键。
- 旁注：`QUEUE_KEY` 深度=1（`msg_queue.c:20`，`xQueueCreate(1,...)`，`xQueueSendFromISR` 满则丢事件），但与本"两次"现象无直接因果。
