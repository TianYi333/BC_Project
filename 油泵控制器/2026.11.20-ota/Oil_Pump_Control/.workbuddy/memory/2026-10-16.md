### 已同步的改动 1：net_comm_task.c —— tcp_recv_cb 区分「异常」与「对端 FIN」
原实现无论 `err != ERR_OK` 还是对端优雅 FIN（`p == NULL && err == ERR_OK`）都一律
`tcp_pcb = NULL`，导致 FIN 场景下 pcb 无人关闭 → **CLOSE_WAIT 孤儿连接**
（症状：PC 看到两条连接 / 设备打印两条 / 心跳只一条 / 重连只断一条）。
现改为：仅异常路径清空 `tcp_pcb`（lwIP 会自行释放）；FIN 路径**故意保留**全局指针，
交主循环 `safe_tcp_close()` 真正 `tcp_close` 释放。

### 已同步的改动 2：ota.c —— 新增 TFTP 接收看门狗（`OTA_TFTP_RX_TIMEOUT_MS` 默认 30s）
解决「开启 TFTP 后一直没收到 / 上位机文件名错且不重试 / 传输中途卡死」会**永久卡在
`OTA_RX_ACTIVE`**、从而拒绝后续 upgrade 命令的问题。实现要点：
- 新增 `g_ota_last_active_tick` / `g_ota_rx_timeout_ticks` / `g_ota_mon_task`；
- 三处喂狗：`tftp_open_cb` 成功 WRQ、`tftp_write_cb` 收到 DATA、`ota_handle_upgrade_start` 开启 TFTP 时；
- 新增独立低优先级任务 `ota_monitor_task`（`ota_mon`，栈 2048，`osPriorityLow`，每秒一查），
  `ota_check_timeout()` 用无符号 tick 差（自动处理回绕）判超时 → 上报
  `upgrade_status{"rx_timeout","no TFTP traffic, session aborted"}` + `ota_reset_session()` → IDLE；
- `ota_start_monitor()` 幂等创建任务，在 `ota_handle_upgrade_start()` 里调用。
