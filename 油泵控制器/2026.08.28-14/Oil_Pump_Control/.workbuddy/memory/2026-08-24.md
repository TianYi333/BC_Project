## 修复 syncif.c sync_from_sysdb 编译告警 -Wmaybe-uninitialized
- 告警：syncif.c:122 `SYS_CONFIG_T tmp;` 是栈变量，随后把 `&tmp` 传给 `fdb_blob_make(&blob, &tmp, ...)`，GCC 看到 `value_buf` 是 `const void *`，无法确认 `fdb_kv_get_blob` 一定会写 `tmp`；即便业务上我已经用 `if(got == sizeof(SYS_CONFIG_T))` 保护，保守的 -Wmaybe-uninitialized 仍不消。
- 修复：把声明改成 `SYS_CONFIG_T tmp = {0};`（零初始化整个结构体），再传给 `fdb_blob_make`。零初始化后无论 KV 是否命中，tmp 都是确定值，告警消除。
- 行为仍保持正确：后续 `if(got == sizeof(SYS_CONFIG_T))` 仅在完整读到一整个 SYS_CONFIG_T 时才 `SysConfig_WriteSnapshot(&tmp)`，否则保留 sys_cfg 现状（即 var_init 阶段 `Cfg_SetDefault(&sys_cfg)` 写入的出厂默认）。首次烧录/Flash 清空场景下不会把栈垃圾覆盖到 sys_cfg。

## 完善 debug_modbus_test_callback（UserCode/Logic/oled_page.c）
- 原占位 "Function Not Implemented"。现实现 Modbus 通讯自检：
  - 进入页面先切 SYS_STATE_SETTING（与工程约定一致，停自动压力控制）；osDelay(150) 等主逻辑识别。
  - 检测项按驱动宏决定：`MOTOR_DRIVER_RS485_SERVO` → 测 Motor + Liquid 两项；`MOTOR_DRIVER_PULSE_STEPPER`（当前默认）或兜底 → 仅测 Liquid。
  - 检测流程：for 每个设备，内部 for 最多 3 次尝试；每次先全屏覆盖画当前设备名(VALUE_FONT 居中)+"Detecting %d/3"(STATUS_FONT 居中)，再发起读；成功则 break 进下一设备，失败重试，3 次后仍失败记 FAIL 再进下一设备；尝试间隔 osDelay(50)。
  - 电机通讯检测用 `Motor_ReadErrCode()`（用户指定）；该函数内部维护 `motor_comm_err_cnt`（成功归零/失败自增），调用后 `motor_comm_err_cnt==0` 即本次通讯成功（注意：RS485 版 ModbusMasterTask 也并发改此计数，属调试页可接受）。
  - 液位传感器读与 ModbusMasterTask 方式相同：`mb_master_read_holding(LIQUID_SLAVE_ADDR, LIQUID_REG_LEVEL, 1U, reg_data)`，`ret==0` 为成功。
  - 检测完成后结果页：draw_menu_header_status("Modbus Test") + 每项 "NAME: OK/FAIL"(VALUE_FONT) + "Long Press Return"(STATUS_FONT)，长按 ENCODER_PUTH_LONG 退出。
  - 设备名用短名 "Motor"/"Liquid"（避免 128px 屏溢出；中文 "检测中" 因 u8g2 内置字体仅 ASCII 故用英文 Detecting 保持 UI 一致）。
